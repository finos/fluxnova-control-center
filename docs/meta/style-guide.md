# Style Guide

This guide provides guidance on writing clear and consistent documentation for the project. This
documentation is primarily intended for developers, operators, and other technical users who are
using or contributing to the project.

This style guide is not meant to be exhaustive. It is intended to provide general guidelines and
best practices for writing documentation for the project. For guidance on specific matters not
explicitly covered in this guide, the
[Google Developer Documentation Style Guide](https://developers.google.com/style) should be
considered implicitly part of this guide. Following its advice is expected unless overridden by
other parts of this guide. The [Highlights](https://developers.google.com/style/highlights) page
presents a good high-level overview and is a good starting point for becoming familiar with the
appropriate style and tone.

For matters not covered in this guide or in the resources cited in this guide, existing Fluxnova or
FINOS documentation may also serve as an example to resolve any questions about style and
formatting.
